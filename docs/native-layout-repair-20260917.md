# SkySend: восстановление оформления штатных блоков, 17.09.2026

Исправлена неполная передача оформления при переходе на Twenty Twenty-Five.
Активная тема и ядро не менялись. Оформление задаётся обычными настройками
блоков и глобальными стилями WordPress, без плагинов, Custom HTML, своего CSS,
пользовательского JavaScript или runtime PHP.

## Что исправлено

- Вертикальное центрирование содержимого семи основных секций; контейнер 1200 px.
- Все семь секций на ширине 1280 px снова по 600 px. На телефоне содержимое
  свободно увеличивает высоту, не обрезается ради фиксированной высоты.
- Партнёрские фотографии над центрированными названиями и описаниями.
- Статистика распределена по всей ширине: четыре показателя на компьютере,
  два в строке на телефоне. Убраны пустые колонки автоматической сетки.
- Центрирование заголовков, подписей провайдеров, карточек безопасности и FastSYS.
- Пропорции изображений и штатная точка фокуса справа; единая типографика.
- Адаптивные размеры заголовков и показателей — штатные fluid-пресеты WordPress.
- Границы и скругления плоских карточек; кнопки клиентского ПО на общей нижней линии.
- Колонки футера выровнены сверху, шесть загрузок в двух колонках на компьютере,
  копирайт и соцсети в общей нижней строке.

Тексты, изображения, контакты, URL и названия вкладок актуальной страницы сохранены.
Изменения пользователя не заменялись старым `content.json`: исходником послужил
свежий штатный WXR-экспорт действующих записей.

## Где редактировать футер

Футер не является содержимым страницы 67, поэтому не появляется среди её блоков.
Это отдельная стандартная часть шаблона 69. Права администратора проверены:
`edit_theme_options=true`, `edit_post(69)=true`. Блокировок редактирования нет.

Путь: **Внешний вид → Редактор → Паттерны → Подвал → SkySend — Футер**.

Проверенный маршрут, открытый именно через этот интерфейс:

http://31.129.98.28/wp-admin/site-editor.php?p=%2Fwp_template_part%2Ftwentytwentyfive%2F%2Ffooter&canvas=edit

В «Обзоре документа» группа называется «Футер — контакты, поддержка и загрузки»;
её колонки также именованы. Шапка и футер остаются настоящими частями шаблона,
не копируются в страницу и не дублируются на сайте.

Известная проблема пустого iframe встроенного браузера не исправлялась правками
ядра. Для обычного визуального редактирования использовать Chrome/Edge, где
пользователь ранее подтвердил работоспособность блоков.

## Проверки и резервная копия

- Проверка штатными сериализаторами той же установки WordPress: 356 блоков
  страницы, 24 футера, 12 шапки; все `invalid=0`, только `core/*`.
- `wp core verify-checksums`, `wp db check` успешны; список плагинов пуст.
- Визуальная проверка навыком Browser: выравнивания, высоты, карточки, футер,
  отсутствие горизонтального переполнения на 1280, 390 и 320 px.
- Три баннера переключаются стандартными вкладками без переполнения на 320 px.

Серверная резервная копия до правок:
`/opt/skysend-backups/20260917-native-alignment/database-before.sql`.
В этом закрытом каталоге также сохранены WXR-снимки этапов проверки.
База и WXR с административными метаданными не помещаются в Git.

`repair.mjs` и `apply-repair.php` — разовые служебные инструменты вне runtime
сайта. Проверяются SHA256 текущего содержимого всех целевых записей; обновление
проводится через WordPress API внутри InnoDB-транзакции с блокировкой точных строк.
При обнаружении новой правки редактора обработка прекращается без публикации.
Не запускать их по старому снимку для дальнейшего редактирования сайта.
Обычные мелкие изменения вносить через редактор WordPress.

Старый режим `build.mjs` без `--repair` относится к первоначальной миграции,
а не к повторному деплою действующего сайта. Повторный импорт миграции остаётся
запрещённым. Экспортированные HTML/JSON в `wordpress/native-blocks` обновлены;
для полного переноса отредактированного сайта нужны действующая база и uploads.
