# Автопрокрутка баннеров, 17.09.2026

Внешняя высота баннера позднее выровнена до 600 px на компьютере;
см. [отчёт по высоте](banner-height-20260917.md). Настройки карусели
и содержимое слайдов не менялись.

Пользователь разрешил использовать плагин после обсуждения ограничения
«строго встроенные блоки, без плагинов». Установлен бесплатный
[Carousel Slider Block for Gutenberg](https://wordpress.org/plugins/carousel-block/),
slug `carousel-block`, версия 2.1.5 из официального каталога.
`wp plugin verify-checksums carousel-block` успешно проверил пакет.

Изменена только оболочка трёх баннеров страницы 67: вместо `core/tabs`
использованы `cb/carousel-v2` и три `cb/slide-v2`. Заголовки, изображения,
реальный логотип ALLVEND и кнопки «Подробнее» перенесены без изменения.
Ссылки остались `#providers`, `#participants`, `#allvend`.
Шапка, футер, глобальные стили, провайдеры и остальные секции не изменены.
Собственный runtime CSS/JavaScript/PHP не добавлен: поведение обеспечивает
немодифицированный плагин с локально поставляемым Swiper.

## Настройки и редактирование

- Один баннер одновременно на всех ширинах, расстояние между слайдами 0.
- Автопрокрутка: 6000 ms; переход: 500 ms; бесконечный цикл включён.
- Пауза при наведении мыши включена; после ручного выбора автопрокрутка
  не отключается навсегда.
- Стрелки и отдельная кнопка паузы не добавлены согласно предыдущим замечаниям.
- Внизу три штатных индикатора для ручного выбора слайда, без видимых цифр.

Редактор: http://31.129.98.28/wp-admin/post.php?post=67&action=edit.
В «Обзоре документа» раскройте «Три баннера» →
«Баннеры — автопрокрутка каждые 6 секунд». Внутри три именованных слайда:
«Провайдеры услуг», «Финансовые условия», «ПО ALLVEND».
Тексты, изображения и кнопки редактируются обычными блоками внутри слайдов.
Чтобы менять интервал, выберите родительскую карусель, откройте настройки
блока справа: `Carousel Settings` → `Autoplay` / `Autoplay speed (ms)`.
Если редактор открыт до публикации, обновите его после сохранения нужных
собственных правок, иначе старая версия может перезаписать новую.

## Проверка

- Проверен полный автоматический цикл: провайдеры → финансовые условия →
  ALLVEND → провайдеры; наблюдение UI каждые 2.5 секунды.
- Проверена пауза при наведении: один баннер оставался активен больше 8 секунд.
- Проверены ручной выбор третьего слайда и загрузка всех картинок/логотипа.
- Browser: ширины 1280, 390 и 320 px без горизонтального переполнения.
- Сериализаторы самого WordPress и установленного плагина: 354 блока,
  `invalid: 0`; вложенное содержимое каждого слайда проверено до/после
  и после round-trip через сериализатор.
- Блоки вне баннеров сравнивались целиком; хеши футера и глобальных стилей
  после публикации остались прежними. У администратора есть право редактировать
  страницу, блок и его скрипт редактора зарегистрированы WordPress.
- `php -l apply-carousel.php` успешен на VM.

Плагин заявляет Tested up to 7.0.4, а сайт работает на WordPress 7.1:
работоспособность подтверждена живой проверкой, не обещанием автора о 7.1.
Встроенная пауза работает при наведении, но нет отдельной кнопки остановки,
автоматической реакции на `prefers-reduced-motion` и паузы при клавиатурном
фокусе; полное соответствие WCAG для автодвижения не заявляется.
Известное ограничение редактора во встроенном браузере описано в отчёте
первоначального переноса: для ручных правок используйте обычный Chrome/Edge.

## Резервная копия и воспроизведение

Закрытый каталог VM: `/opt/skysend-backups/20260917-banner-carousel/`:
база до и после, свежий WXR страницы до конвертации и применённый proposal.
Эти данные и пароли не помещены в Git. Пакет плагина тоже не копируется
в репозиторий: его источник и версия сохранены в `plugins.json`.

На новой установке перед импортом сохранённых блоков установите плагин:

```sh
wp plugin install carousel-block --version=2.1.5 --activate
wp plugin verify-checksums carousel-block
```

`carousel.mjs` — одноразовый сборщик, который читает актуальный WXR страницы
с прежними штатными вкладками и использует сериализаторы установленного плагина.
`apply-carousel.php` выполняется только через WP-CLI и применяет только
страницу 67 при совпадении исходного хеша, с транзакцией и блокировкой строки.
После публикации редактируйте в WordPress: не запускайте повторно миграцию
или прежние `--repair` / `--providers-layout` поверх последующих правок.
Сохранённый manifest не предназначен для повторного применения к уже
обновлённой странице.
