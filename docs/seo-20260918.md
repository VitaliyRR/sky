# SEO SkySend, 18.09.2026

На тестовой ВМ http://31.129.98.28/ исправлена карта сайта и восстановлены
SEO-метаданные готовым SEOPress Free 10.2. Оформление и содержание лендинга,
шапки, футера, шаблона и глобальных стилей не менялись; хеши пяти сущностей
совпали до/после. Дополнительного runtime-кода, Custom HTML или MU-плагинов нет.

## Что настроено

- WordPress обновлён с 7.1 до официального стабильного 7.1.1. Русский пакет
  7.1.1 не удалось скачать, поэтому применён официальный en_US-пакет;
  `WPLANG=ru_RU` и русский язык админки сохранены.
- Нативные `wp-sitemap.xml` и `wp-sitemap-posts-page-1.xml`: HTTP 200,
  корректный XML. В карте только опубликованная главная, без черновиков,
  медиа и удалённых партнёрских страниц. Обе XSL: 200.
- `robots.txt`: HTTP 200, разрешает индексацию и указывает на рабочую нативную
  карту; `blog_public=1`, у главной нет `noindex`.
- Один title: «SkySend — система приёма платежей»; один H1,
  meta description длиной 157 символов, один canonical текущего сайта.
- Open Graph и X Cards: название, описание, URL и реальное изображение
  первого баннера, 1774 × 887, доступное по HTTP 200. X handle: `@infsysgroup`,
  карточка `summary_large_image`.
- Стандартные JSON-LD WebSite и Organization: SkySend, URL, существующий
  логотип, официальные контакты и уже используемые в футере соцсети.
  Адрес офиса, ИНН, юридическое название, даты и новые показатели не добавлены.
  Free UI предоставляет один ContactPoint — контакты подключения, `sales`;
  поддержка отдельно остаётся в редактируемом футере и тексте страницы.
- 14 старых партнёрских адресов и старая карта сохраняют корректные 301.
  Неизвестный адрес отдаёт настоящий 404 и `noindex`; поиск тоже `noindex`.
- Метатеги description, canonical, Open Graph/X не дублируются.

Описание использует только сведения существующего лендинга:

> SkySend — система приёма платежей. ПО ALLVEND, FastSYS 5 и клиентские приложения
> для платёжных агентов и устройств самообслуживания. Подключение и поддержка.

Платная лицензия и подключения аналитики, AI-сервисов или поисковых API
не требуются и не настроены. В SEOPress включены только модули Title и Social.
Его собственный XML-модуль отключён **обоими** параметрами:
`seopress_toggle.toggle-xml-sitemap=0` и
`seopress_xml_sitemap_option_name.seopress_xml_sitemap_general_enable=0`.
После изменения выполнен обычный `wp rewrite flush` отдельным процессом,
без `--hard`: восстановлены маршруты карт, правила Apache с 301 сохранены.

## Восстановление и дальнейшая публикация

Для переноса текущего сайта нужна полная согласованная база, uploads,
официальная тема и оба плагина из `wordpress/native-blocks/plugins.json`.
Git содержит настройки и разовые инструменты, но не живую WordPress-базу.
Обычный `git pull` не запускает импорт и не перезаписывает редакторские правки.

Разовая первоначальная настройка SEOPress уже выполнена. Только для свежего
восстановления этой же базы без SEO-настроек, после резервирования и проверки ID:

```sh
wp --allow-root --path=/var/www/skysend plugin install wp-seopress --version=10.2 --activate
wp --allow-root --path=/var/www/skysend eval-file /opt/skysend/wordpress/native-blocks/configure-seo.php /opt/skysend/wordpress/native-blocks/seo-settings.json
wp --allow-root --path=/var/www/skysend rewrite flush
```

Не удаляйте `skysend_seo_setup_complete` ради повторного применения файла:
последующие правки вносятся через админку. Скрипт не является плагином,
не подключается к теме и не должен находиться в webroot. Не запускайте его
одновременно с ручным редактированием SEO-настроек.

После переноса на ВМ компании остаётся:

1. Переключить согласованный DNS, выпустить TLS-сертификат и выбрать единый
   основной HTTPS-домен, настроить 301 с HTTP и альтернативного www-варианта.
2. Штатно заменить тестовый URL в базе, включая сериализованные блоки,
   медиа и настройки SEOPress; обновить WordPress home/siteurl и физический
   robots.txt. Не ограничиваться заменой только двух site options.
3. Повторно проверить canonical, OG/JSON-LD URL, изображения, robots и карты
   на новом домене, отсутствие mixed content и старые перенаправления.
   Read-only скрипт принимает новый BaseUrl.
4. Закрыть тестовую копию от индексации или ограничить доступ, чтобы не
   оставлять индексируемый дубликат боевого сайта.
5. В кабинетах владельца Google Search Console и Яндекс Вебмастер подтвердить
   права на боевой домен, отправить карту и проверить фактическую индексацию.
   Эти кабинеты в рамках текущей настройки не подключались.

Техническая SEO-подготовка тестовой версии завершена; фактическая индексация
и позиции не гарантируются наличием метатегов. Финальная проверка боевого
домена возможна только после переноса, DNS и HTTPS.
